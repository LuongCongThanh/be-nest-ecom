### 📂 Module folder layout (bắt buộc cho mọi module trong `src/modules/`)

```text
modules/<feature>/
├── <feature>.module.ts                ← Nest module wire-up
├── <feature>.controller.ts            ← HTTP endpoints (>=1, có thể split nếu nhiều)
├── <feature>.service.ts               ← Business logic
├── <feature>.repository.ts            ← Data access (optional, chỉ khi query logic đủ phức tạp)
├── <feature>.service.spec.ts          ← Unit test sống cạnh service
├── dto/
│   ├── create-<feature>.dto.ts
│   ├── update-<feature>.dto.ts
│   └── <feature>-response.dto.ts      ← Output DTO (nếu cần transform riêng)
└── types/                             ← Optional, internal types
    └── *.types.ts
```

## 🔗 Path aliases

Bắt buộc setup trong `tsconfig.json` + `nest-cli.json` + `jest.config` (cho ts-jest).

```json
{
  "compilerOptions": {
    "baseUrl": "./src",
    "paths": {
      "@common/*": ["common/*"],
      "@config/*": ["config/*"],
      "@shared/*": ["shared/*"],
      "@modules/*": ["modules/*"],
      "@infrastructure/*": ["infrastructure/*"],
      "@jobs/*": ["jobs/*"]
    }
  }
}
```

**Quy tắc dùng**:

- Import giữa các module → dùng alias `@modules/users` thay vì `../../users`.
- Import nội bộ trong cùng module → relative `./dto/create-user.dto`.
- KHÔNG dùng alias cho file cùng folder (ugly).

## 📝 File suffix conventions (chuẩn hoá)

| Suffix | Loại | Ví dụ |
|--------|------|-------|
| `*.module.ts` | NestJS module | `users.module.ts` |
| `*.controller.ts` | HTTP controller | `users.controller.ts` |
| `*.service.ts` | Service (business logic) | `users.service.ts` |
| `*.repository.ts` | Repository (data access) | `users.repository.ts` |
| `*.dto.ts` | DTO class (input/output) | `create-user.dto.ts` |
| `*.entity.ts` | Domain entity type (nếu có) | `user.entity.ts` |
| `*.guard.ts` | Guard | `jwt-auth.guard.ts` |
| `*.decorator.ts` | Decorator | `roles.decorator.ts` |
| `*.interceptor.ts` | Interceptor | `logging.interceptor.ts` |
| `*.filter.ts` | Exception filter | `global-exception.filter.ts` |
| `*.pipe.ts` | Pipe | `parse-uuid.pipe.ts` |
| `*.middleware.ts` | Middleware | `correlation-id.middleware.ts` |
| `*.validator.ts` | Custom validation helper/constraint | `is-strong-password.validator.ts` |
| `*.exception.ts` | Custom exception class | `business.exception.ts` |
| `*.strategy.ts` | Passport strategy | `jwt.strategy.ts` |
| `*.adapter.ts` | External service adapter impl | `s3.adapter.ts` |
| `*.sender.ts` | Email sender impl | `resend.sender.ts` |
| `*.job.ts` | Cron job | `cleanup-pending-orders.job.ts` |
| `*.spec.ts` | Unit test | `users.service.spec.ts` |
| `*.e2e-spec.ts` | E2E test | `checkout.e2e-spec.ts` |
| `*.types.ts` | Shared types (không class) | `vnpay.types.ts` |
| `*.factory.ts` | Test data factory | `user.factory.ts` |

**Quy tắc**:

- File name **kebab-case** + suffix. Vd `create-user.dto.ts`.
- 1 file = 1 export chính (class/interface/const). Tránh barrel quá rộng.
- `index.ts` chỉ ở folder dùng làm barrel public API (vd `config/index.ts`).

## 📚 Import order convention

Mỗi file import theo thứ tự (ESLint enforce qua `eslint-plugin-import`):

```typescript
// 1. Node built-in (rare)
import * as path from 'node:path';

// 2. External packages
import { Module } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';

// 3. Internal aliases (alphabetical by alias)
import { CurrentUser } from '@common/decorators/current-user.decorator';
import { PaginationDto } from '@shared/dto/pagination.dto';

// 4. Module-relative imports
import { UsersService } from './users.service';
import { CreateUserDto } from './dto/create-user.dto';
```

## 🎨 Naming conventions

| Kind | Convention | Example |
|------|------------|---------|
| **Class** | PascalCase | `UsersService`, `JwtAuthGuard` |
| **Interface** | PascalCase, prefix `I` cho contracts | `IEmailSender`, `IStorageAdapter` (chỉ contract) |
| **Type alias** | PascalCase | `JwtPayload`, `OrderState` |
| **Enum** | PascalCase, value `UPPER_SNAKE` | `Role.ADMIN`, `OrderStatus.PENDING` |
| **File** | kebab-case + suffix | `create-user.dto.ts` |
| **Folder** | kebab-case (plural cho modules) | `users/`, `addresses/`, `orders/` |
| **Variable / Method** | camelCase | `getUserById`, `updatedAt` |
| **Constant** | SCREAMING_SNAKE_CASE | `MAX_RETRY_ATTEMPTS`, `JWT_EXPIRES_IN` |
| **DB column** | snake_case (Prisma sẽ map qua `@map`) | `created_at`, `email_verified` |
| **DB table** | snake_case plural | `users`, `order_items` |
| **API endpoint** | kebab-case plural | `/users`, `/order-items` |
| **Query param** | camelCase | `?page=1&limit=20` |
| **JSON field** | camelCase | `{ "createdAt": "..." }` |

**Module folder = plural** (`users/` not `user/`). Module class = `UsersModule`.

## 🚦 Quy tắc thư mục

| Quy tắc | Áp dụng |
|---------|---------|
| **Không cross-import module nội bộ** | `modules/orders/` KHÔNG import từ `modules/users/` private files. Chỉ qua exported `UsersModule` service. |
| **Common không import Module** | `src/common/*` KHÔNG được import bất kỳ thứ gì từ `src/modules/*`. Một chiều. |
| **Infrastructure không có business logic** | `src/infrastructure/*` chỉ adapter pattern. Logic ở `src/modules/*`. |
| **Jobs gọi service, không trực tiếp Prisma** | `src/jobs/*` inject service tương ứng, không query DB tay. |
| **DTO không reference Prisma model** | DTO độc lập với Prisma generated types. Map qua mapper trong service. |
| **Test cạnh code** | Unit test sống cạnh source (`*.spec.ts`). E2E riêng `test/e2e/`. |
| **1 module = 1 bounded responsibility** | Không có "utils" module catch-all. |

## 🎯 Áp dụng vào Phase B (Tuần 1–4)

Khi bắt đầu Tuần 1 — task `01-bootstrap-nestjs`, **TẠO ĐÚNG** layout này từ đầu:

```text
src/
├── main.ts
├── app.module.ts
├── common/
│   └── prisma/ (Tuần 1)
├── config/
│   └── env.validation.ts (Tuần 1)
├── shared/
│   ├── dto/
│   └── utils/
├── modules/
│   └── health/ (Tuần 1)
└── infrastructure/ (empty, tạo dần)
```

**KHÔNG được**: làm flat `src/auth.module.ts` rồi nói "sẽ refactor sau". Refactor sau = không bao giờ refactor.

**Cũng không nên**: dùng file structure này để khóa cứng generic base repository hay engine search cụ thể cho MVP. Đây là file về **shape**, không phải nơi giữ mọi quyết định vi mô.
