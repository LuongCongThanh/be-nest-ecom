Rule #1: Docs trước, tutorial sau
Đừng bắt đầu bằng YouTube. Đọc NestJS Docs → thực hành trong project → khi bí thì mới xem tutorial. Bạn sẽ hiểu sâu hơn 3x so với học theo video từ đầu.

Lợi thế của bạn so với người mới học
Front-end background là vũ khí, không phải điểm yếu

Bạn đã biết những thứ mà người mới mất hàng tháng để học:

  • TypeScript — NestJS xây hoàn toàn trên TypeScript. Bạn đã quen syntax, type system, async/await
  • HTTP & API — Bạn đã gọi API hàng ngày từ phía client. Giờ chỉ cần lật ngược góc nhìn sang server
  • Component thinking — Module trong NestJS giống hệt Component trong React: đóng gói, có dependency, có lifecycle
  • JSON & Data structures — Request/Response body, DTO đều là JSON bạn đã quen xử lý
  • Git & tooling — Dev workflow, PR, code review không cần học lại
  • Debug mindset — Kỹ năng debug từ front-end áp dụng trực tiếp: đọc error message, trace stack, isolate vấn đề

4 phương pháp học hiệu quả nhất
Dùng song song, không chỉ dùng một

📚 Read → Build loop

Đọc 1 section trong NestJS Docs → implement ngay trong project → lặp lại. Đừng đọc hết docs rồi mới code.

🔍 Reverse Engineer

Khi gặp code mình viết rồi nhưng không hiểu rõ: đọc lại, xoá đi, tự viết lại từ memory. Nếu làm được → đã học thật.

❓ Teach back

Sau khi học xong 1 concept, thử giải thích cho tôi nghe bằng lời của bạn. Điểm nào giải thích không được = điểm cần học thêm.

🐛 Debug intentionally

Khi code lỗi, đừng chỉ fix. Hỏi: "Tại sao lỗi này xảy ra?" Hiểu root cause là học tốt nhất.

Bẫy phổ biến nhất: Tutorial hell
Xem 10 video YouTube rồi cảm thấy "đã hiểu" nhưng tự code không được. Giải pháp: 20% xem/đọc, 80% tự làm. Nếu bạn đang xem nhiều hơn làm — đó là dấu hiệu cần điều chỉnh.
🚀
Bước tiếp theo ngay hôm nay
Cụ thể, có thể làm ngay

Bạn vừa hoàn thành Refresh Token Rotation — đây là feature khá phức tạp. Câu hỏi bây giờ là: bạn có thể giải thích lại cơ chế đó không?

Thử ngay: Nói cho tôi nghe — "Tại sao Refresh Token cần rotation? Nếu không có rotation thì gì xảy ra?" — bằng lời của bạn. Đây vừa là cách kiểm tra kiến thức, vừa là bước đầu xây dựng skill "explain to others" — kỹ năng cốt lõi của senior developer.
