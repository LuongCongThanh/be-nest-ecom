NestJS Deep Dive

NestJS hoạt động như thế nào?

Giải thích từ code thật trong be-nest-ecom — không phải ví dụ trừu tượng. Mỗi concept đều có file thật để bạn mở ra xem.

1

App khởi động như thế nào? (Bootstrap)

Mọi thứ bắt đầu từ một file duy nhất: src/main.ts

import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api/v1', { exclude: ['health'] });

  await app.listen(3000);
}
bootstrap();
💡
Tại sao exclude: ['health']? Route /health cho load balancer check — không cần prefix /api/v1/. Load balancer không biết version API, nó chỉ cần biết server còn sống không.

Khi NestFactory.create(AppModule) chạy, NestJS đọc AppModule và xây dựng toàn bộ cấu trúc app. Đây là quá trình "boot":

① main.ts
Entry point. Gọi NestFactory.create(AppModule)
src/main.ts
↓
② AppModule đọc imports
NestJS đọc decorator @Module({}), tìm tất cả modules cần load
src/app.module.ts
↓
③ IdentityModule, PrismaModule, ... được khởi tạo
Mỗi module khai báo providers của mình — NestJS instantiate (new) tất cả providers
src/modules/identity.module.ts
↓
④ App lắng nghe trên port 3000
Từ đây HTTP requests có thể đến
2

Module là gì? Đọc IdentityModule của bạn

Module là đơn vị tổ chức code. Mở file này và nhìn vào 4 key:

// src/modules/identity.module.ts — code THẬT của bạn

@Module({
  imports:     [PrismaModule, PassportModule.register({ defaultStrategy: 'jwt' })],
  controllers: [AuthController],
  providers:   [AuthService, TokenService, JwtStrategy],
  exports:     [TokenService],
})
export class IdentityModule {}

imports: [...]

Module này cần dùng gì từ module khác. PrismaModule → để AuthService có thể gọi database. Không có đây, PrismaService sẽ không được inject.

controllers: [...]

Các class xử lý HTTP request. AuthController nhận POST /auth/login, /auth/register... NestJS biết route nào thuộc controller nào qua đây.

providers: [...]

Các class được NestJS quản lý và có thể inject vào nhau. AuthService, TokenService, JwtStrategy — tất cả đều là providers.

exports: [...]

Provider nào cho phép module khác dùng. TokenService được export vì module khác (ví dụ UserModule sau này) cần verify token.

🔑
Mental model: Module = hộp kín Mọi thứ trong module mặc định là private. Module khác KHÔNG thể dùng AuthService của bạn trừ khi bạn exports nó. imports là cách mở khóa dependencies từ module khác vào.
3

Request đi từ đâu đến đâu?

Khi client gọi POST /api/v1/auth/login, request đi qua các lớp sau theo thứ tự:

Lớp Tên Việc làm trong be-nest-ecom
1 Middleware CORS, logging (chạy trước mọi thứ, không biết route là gì)
2 Guard JwtAuthGuard kiểm tra token. Nếu route có @Public() → bỏ qua
3 Interceptor Logging request/response time, transform response (nếu có)
4 Pipe ValidationPipe validate body DTO (class-validator). Sai → reject ngay
5 Handler Method trong Controller chạy. Gọi authService.login(dto)

Ví dụ cụ thể với POST /auth/login:

// 1. Guard đọc decorator @Public() → login là public → cho qua
// 2. Pipe: validate LoginDto { email, password } → đúng format → cho qua
// 3. Handler chạy:

@Public()                    ← Guard thấy cái này, bỏ qua JWT check
@Post('login')
@HttpCode(HttpStatus.OK)
async login(@Body() dto: LoginDto) {   ← Pipe validate dto trước khi vào đây
  return this.authService.login(dto);  ← Gọi service
}
⚡
Tại sao @HttpCode(HttpStatus.OK)? NestJS mặc định trả 201 Created cho POST. Login không tạo resource mới — nó chỉ xác thực. Nên phải override về 200 OK bằng decorator này.
4

Dependency Injection — NestJS new() hộ bạn

DI là cơ chế NestJS tự tạo và truyền instance vào class. Bạn không phải tự new AuthService().

Nhìn vào AuthController của bạn:

export class AuthController {
  constructor(private readonly authService: AuthService) {}

  async login(@Body() dto: LoginDto) {
    return this.authService.login(dto);  ← dùng được ngay
  }
}

NestJS thấy AuthController cần AuthService → tự tìm trong providers của module → tự khởi tạo và truyền vào. Bạn chỉ cần khai báo trong constructor.

Chuỗi dependency trong project của bạn:

IdentityModule
AuthController cần → AuthService
↓ inject
AuthService cần → TokenService, PrismaService, UserRepository
↓ inject
TokenService sign/verify JWT
PrismaService query database (từ PrismaModule)
🧩
So sánh với React để dễ hiểu hơn Trong React, bạn dùng useContext() để lấy global state mà không cần pass props qua nhiều lớp. DI trong NestJS tương tự — class nói "tôi cần cái này" và NestJS cung cấp, không cần manual wiring.
5

Decorators — metadata gắn lên code

Decorator là hàm bắt đầu bằng @ — chúng gắn thêm thông tin (metadata) lên class, method, hay parameter. NestJS đọc metadata này lúc runtime để biết phải làm gì.

Phân tích một handler trong AuthController của bạn:

@Post('logout')            ← "route này là POST /auth/logout"
@HttpCode(HttpStatus.NO_CONTENT) ← "trả 204 thay vì 200"
@ApiBearerAuth()          ← "Swagger: route này cần Bearer token"
async logout(
  @CurrentUser('id') userId: string,  ← "lấy user.id từ request.user đã verify"
  @Body() dto: RefreshDto              ← "parse body thành RefreshDto"
) {
  await this.authService.logout(userId, dto);
}

Class decorators

@Controller('auth') — tất cả route trong class này có prefix /auth

@Module({}) — khai báo đây là một NestJS Module

Method decorators

@Get(), @Post(), @Delete() — HTTP verb và path

@Public() — custom decorator bạn tự tạo, Guard đọc nó

Parameter decorators

@Body() — parse request body
@Param('id') — lấy route param
@CurrentUser('id') — custom decorator của bạn

Injectable decorator

@Injectable() — đánh dấu class này là Provider, NestJS DI có thể quản lý và inject nó vào nơi khác

Bức tranh toàn cảnh — mọi thứ kết nối

── REQUEST: POST /api/v1/auth/login ──────────────────────────────────────

HTTP Request
    │
    ▼
[ Middleware ]  CORS check, Request logging
    │
    ▼
[ JwtAuthGuard ]  Thấy @Public() trên handler → cho qua
    │
    ▼
[ ValidationPipe ]  Parse body → LoginDto { email: "a@b.com", password: "..." }
    │                              Sai format → trả 400 ngay
    ▼
[ AuthController.login() ]     ← handler chạy
    │   return this.authService.login(dto)
    ▼
[ AuthService.login() ]
    │   validate user, check password
    │   gọi tokenService.generateTokenPair()
    ▼
[ TokenService ]  sign JWT access token + refresh token
    │
    ▼
[ UserRepository ]  lưu refresh token hash vào DB qua Prisma
    │
    ▼
Response: 200 { accessToken, refreshToken }
